# pair-wise-yf-49 法庭证据展示与庭审顺序控制

源提示词摘要：法官、书记员和双方代理人共同维护庭审证据目录，控制当前展示、证据顺序、敏感信息遮罩、计时、异议分支和庭审阶段；操作屏与公开屏分离，离线时仍可展示并能恢复本地快照。

## 技术栈

React19、TypeScript、Vite、Arco Design、Redux Toolkit、RTK Query、React Router、React Hook Form、Zod、i18next。

## 本地运行

```bash
npm install
npm run dev
npm run build
```

## 控制权租约协议（证据目录并发控制）

证据目录的所有写操作（排序、选中、展示、完成、敏感遮罩）统一走 `submitOp`，只认控制权租约，防止旧页面在网络抖动后覆盖新控制端：

- **按角色领取**：书记员/法官通过 `acquireControl` 领取租约（带 `epoch` 与锚定的目录修订号）；租约被他人持有时进入候补队列，绝不覆盖现租约。
- **心跳与回滚**：持有者每秒续心跳，超过 TTL（5s）未续即判定心跳失败，旧租约回滚（`leaseEngine.sweep`）。
- **候补按序号接管**：候补队列中序号最小的在线设备自动获得新 `epoch`；队首离线则顺延。
- **旧端停在待合并区**：断网设备若自认仍持有租约，操作只入 `pendingOps`，不改目录；无租约/候补/纯离线操作直接被门禁拒绝。
- **回网重放**：按「租约 epoch → 租约内修订号」重放；同一证据已经公开（展示中/已展示）则跳过旧操作；旧顺序基于的顺序修订号过期则跳过，不覆盖新顺序；同一证据的遮罩开启排在展示之前生效。
- **计时重算**：顺序改动后当前为「待展示」的证据立即按新时长重算计时，展示中证据保留剩余计时。
- **旧数据升级**：缺少租约和角色的旧版 localStorage 文档仍可打开，由当前书记员补上默认控制权（epoch 1）。

模拟方式：控制台内置两个席位（书记员/法官），可切换当前席位、调整角色、对单个席位断网/回网；右侧「待合并区与重放审计」实时展示缓存操作与合并/跳过结果。
